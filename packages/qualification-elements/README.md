# Canonical UI export qualification

This offline fixture consumes only `@capiro/ui` public component exports. The UI package owns all seventeen adopted sources and the sixteen recorded Meri Figma 3.4 additions (verified by inverse rewrite against their recorded pinned upstream hashes, with four exact recorded owner adaptations); there is no qualification vendor copy. It is not a product screen, server, model loop or backend endpoint.

`baseline/component-pins.json` and `baseline/package-lock.json` preserve the original NEW Meri367-package inventory/lock as immutable historical data. The workspace owner's root lock is the only active install lock. Exact source/provenance ownership for both real packages is generated into `promotion-pins.json` by `node generate-pins.mjs`; `node generate-pins.mjs --check` refuses drift. Source generators do not execute components. Metadata is a trusted owner anchor, not authorization or hostile-filesystem proof.

After the workspace owner installs exact dependencies with scripts disabled, run `npm run typecheck`, then prepare a fresh receipt using `node ssr-build.mjs VERIFIED_TOOL_ROOT NEW_OUTPUT_ROOT`. Set `MERI_ELEMENTS_SSR_RECEIPT` and `MERI_ELEMENTS_SSR_RECEIPT_SHA256` to its exact result before `npm test`. `MERI_ELEMENTS_SSR_CAPTURE_ROOT` optionally selects a new external evidence directory. No ambient bundle regeneration occurs during tests. `npm run check` runs typecheck and the eighteen cases currently declared in `qualification.test.mjs`, including one cached real SSR outcome; the receipt-bound cases fail without the two receipt variables. Official esbuild0.28.2 pins cover Windows x64, Linux x64 and Linux ARM64; the two original platform records are unchanged. The ARM artifact's npm integrity, package metadata and AArch64 ELF bytes were verified before adding its pin. The existing shipping entry selects the actual Linux platform and fails on unsupported or missing pins, with no emulation/fallback. Actual Linux execution and the resulting fresh SSR receipt still require the native qualification run.

The original20-second monotonic/inner timer,25-second child spawn,512KiB output bound, four synthetic/hostile input triples, disabled controls, inverse vendor adaptation, static58exports, dependency/license closure, source/output/receipt drift negatives and restricted-operation guards remain. New layout metadata spans both canonical packages and actual resolver inputs. Receipt schema2 distinguishes this new two-package layout; old receipts cannot attest it.

No Tailwind installation or CSS processor is authorized here. CSS is retained unprocessed source; the web caller styles the adopted button with CSS modules. Browser build/hydration, visual/accessibility/responsive/theme, safe Markdown/plugin activation, live transport/auth/authorization and complete release notices/security remain open. In-process function/import guards are qualification checks, not OS isolation. Backend source removal, independent review and integration acceptance remain separate.
