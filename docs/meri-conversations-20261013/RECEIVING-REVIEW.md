## Concrete integration obligations

1. **Make admitted observed progress the sole reconnect authority.** A submit receipt's lastSequence does not prove any event was observed; its cursor starts0. History after40 with20 admitted events may acknowledge through60 even if lastSequence is200. Use its nextSequence or an explicit offset within that page's observed interval, never200. A new cursor returned by receiveConversationEvent replaces the old single-use cursor only after all local frame/current-view checks succeed. At10000 identities the unchanged cursor remains valid; fetch/admit a new history checkpoint and expose any deliberately omitted prefix. Current legacy ConversationProjection starts0, has no partial-page hydration and owns an unbounded pending/identity history. Assigning its numeric cursor to lastSequence would invent observations. References: receiver60–73; projection.ts constructor/accept/drainPending.

2. **Do not silently change the legacy replay contract.** Existing projection accepts exact duplicates, buffers gaps, and accepts multiple runs/attempts within tenant/actor/conversation. The0.1.3 receiver requires exactly after+1, unused event ID and exact full run binding/scopes. Identical replay, gaps, or changed attempt/worker/fence are errors for that cursor. Stop the affected subscription with the old admitted cursor retained; recover by an explicit current history admission. Do not swallow a receiver error and advance using the legacy projection. Existing21 transport controls, including duplicate219, gap263 and multiple-run278, must stay meaningful and unchanged for the legacy factory; add separate public-receiver composition tests.

3. **Admission must be atomic with respect to the outer frame.** guardUiChunk currently invokes validateEvent at80 before checking chunk.id at89; a stateful receiver inserted directly into that callback could consume a cursor before the outer ID mismatch throws. Check allowed frame kind, required exact ID, transient custom-event policy, current lifetime/expiry/context and serial event order before committing the returned cursor or notifying observers. Preserve rejection of native reasoning/tool/text frames.0.1.3 has no current-authority callback: the caller must check authority before and after asynchronous boundaries and for every frame. Existing onData is deliberately not admission authority.

4. **Use the real upstream factory and its actual reconnect.** Pinned ai7.0.137 HttpChatTransport232–289 derives api+/{encoded chatId}/stream and forwards the supplied resume header, matching the new fixed route exactly. Retain external Chat, resumeStreamIsReplay=false and useChat({chat,resume:false}); inline useChat({transport}) loses the extra transport flags at this pin. Do not build another SSE parser, chat loop or retry loop. The existing prepareSendMessagesRequest spreads arbitrary body fields; the public subscribe body must instead be the admitted closed command only. Keep submit JSON separate from AI SDK subscription sendMessage semantics, and do not auto-submit or auto-resubscribe from a side-effecting UI handler.

5. **Receiving bounds are not network bounds.** Installed provider-utils5.0.58 parse-json-event-stream.ts uses nonfatal TextDecoderStream and EventSourceParserStream without a buffer cap. DefaultChatTransport decodes before the existing guard sees objects. Re-encoding decoded data for receiveConversationEvent does not prove original-wire strict UTF8, nor prevent a huge unfinished SSE frame allocation. Keep the upstream parser but add a documented finite byte/time policy in the authenticated fetch/stream boundary before it, including cancel/late-body cleanup. A bounded subscription-segment budget can safely stop observation and require explicit reconnect from the admitted cursor; it is not a claim that the entire conversation fits one event cap. Do not claim the package's buffered2MiB check closes this gap by itself.

6. **Bind the first view and every replacement to the current session.** Compare the admitted run's tenant/actor/conversation/run against the server-selected bootstrap context and the applicable selected-client scope. The bootstrap does not supply attempt/worker/fence, so do not invent those echoes: the admitted run supplies the full view used by subsequent receiver correlations. Always pass currentView when already known, preserving immutable request/window/skill pins. A different valid-shaped response is not the current view. Cancel success contains no identity; correlate it to the captured request/session/lifetime externally and never apply a late result to a replacement view. HTTP401/403 and local expiry revoke visibility/subscription even if the body is malformed; they do not prove a prior submit/cancel rolled back.

7. **Reuse the canonical session owner without widening capabilities.** ApplicationBoundary keys user/session/org and replaces client-scoped providers; SelectedClient distinguishes current,loading,unavailable. OpaqueSessionController already owns bootstrap, lifetime abort, idle expiry and disposal; host presentation keeps same-client loading mounted/hidden and blocks dispatch. New receiving must additionally stop admitting stream frames while that view is unavailable, retaining observed cursor/draft for same-client recovery without granting access. On identity/client replacement, disposal or expiry, reject superseded requests/chunks, clear credential/content references and dispose only the subscription. Legacy transport.close only records a flag and forwards close; new composition must also refuse later calls on a disposed handle. No close/back/navigation/reader cancellation may POST durable cancel. Existing connection-config permits bootstrap only when action or document is enabled; add an explicit conversation capability choice if the new surface is enabled, without turning action/doc flags on or making public Onboard/Planner bypasses authorize Meri.

8. **Treat write ambiguity separately from observation failure.** Preserve original requestId and exact prompt/window/skill through a lost submit acknowledgement; no blind new UUID or changed-body retry. Native service documents exact request replay, but a receiver-valid replayed flag is not new browser authority. Cancellation is an explicit command and its terminal state must be shown truthfully. End-of-stream, finish, HTTP204, hook ready, timeout or reader abort never imply run completion. Only admitted run.status or authenticated history supplies durable state. Error codes are content-free and supply no generic rollback/retry guarantee.

## Minimal cohesive composition

Keep the canonical packages/meri-client guard, external Chat and React facade. Add one narrow conversation-receiving composition at that transport boundary owning the admitted view/cursor and observed-history presentation; use public0.1.3 imports, no mirrored DTOs or private backend implementation. Retain the legacy entry/tests. Give partial-history hydration an explicit admitted-page interface (and visible omitted-prefix/hasMore state), not a caller-provided numeric cursor. A local bounded presentation list may discard old display rows, but it must not manufacture receiver checkpoint provenance.

At the app boundary, a conversation port/host should reuse the opaque-session lifetime and existing session/client composition, while a root-owned fixed same-origin proxy enforces the five known routes/methods, approved origin, current credentials, no redirects/cache and bounded network resources. Keep conversation submit/cancel attempt intent separate from subscription disposal. Existing feature rendering consumes admitted events and safe error codes; do not replace the Meri runtime or add an agent loop. Mount/flag activation remains explicit and unavailable when unconfigured.
