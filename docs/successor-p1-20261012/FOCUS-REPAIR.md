# Independently discovered modal focus repair

During successor accessibility review, disabling a focused Save button or field allowed settled Tab focus to escape an open Files dialog into the document/browser chrome. This was inherited shared behavior, not a regression introduced by the feature repairs. The unchanged independent folder-save control failed before the repair and passed afterward.

The shared Portfolio Dialog now remembers contained focus through React capture, including child autoFocus during portal commit. A small dedicated `dialog-focus.ts` hook observes disabled-attribute changes. It restores focus only when the remembered control or its ancestor became disabled, focus remains on that disabled control or dropped to the body, the document is focused, and this dialog is the top open modal. Nested portalled child focus is excluded. The observer is cleaned up on close/unmount. Radix retains ownership of tab trapping, portal layers and normal focus restoration; vendor source is unchanged.

This is one narrow UI lifecycle responsibility, with no service, data, authorization, browser storage or route behavior. The hook and changed Dialog function are below existing function/file review thresholds. Source architecture still has 413 visible signals:389 reviewed,24 inherited unreviewed,0 blocking and0 boundary errors.

It verifies focus containment while the request is held, after an uncertain receipt, and after Escape returns focus to the opener. Those4 cases and10 existing shared/profile dialog checks pass. An intermediate implementation missed the autoFocus timing edge; its two failures and the final correction are preserved.
