# Website task selection

The conversation composer now offers the enabled configurations for its current chat through `POST /clio/site-workflows/catalog`. Core owns the catalog, native session and current conversation/client access. The existing browser-safe manifest receiver validates responses; the existing conversation draft journal retains only the exact site/task/version/hash selection. Runtime still resolves the current configuration on execution. A listed task does not activate a browser, grant approval or preserve a website login.

The existing Capiro query lifetime aborts replaced reads and discards old responses. The picker mounts only for the current conversation port. Refresh removes old options during the request; a saved pin missing from the returned catalog remains visibly stale until explicitly replaced or cleared, and runtime refuses it. Selection changes preserve the other draft inputs.

Author responsibility assessment (2026-10-29, not an independent review): `SessionComposer` remains a presentation composition boundary; its addition only supplies the current chat and existing selection owner. It adds no authorization, transport or persistence owner. `SiteWorkflowPicker` owns one cohesive selection interaction: current query, exact-pin options, status and explicit change. Splitting its short render branches would obscure that interaction without creating a separate responsibility. Its dependency direction remains feature to shared query/selection foundations and published contracts.

Validation: current native-user access, expired session and client/chat withdrawal run against isolated ordinary-role PostgreSQL. Chrome covers selection/reload, stale version replacement, clear, denied/malformed/disabled catalogs and old-chat response withdrawal. Focused frontend contracts, TypeScript and lint are checked. Builds, deployment, independent review, initial site choices and live authenticated website qualification remain held under the user's instructions.
