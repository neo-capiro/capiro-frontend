- Hub heading and relationship layout labels now match the new frame. The scope option reflects the count of **available** profiles returned to the account. The help and explanatory copy keeps the access boundary explicit; Figma's unqualified statement that anyone can browse every activity would promise records the authorized operations may not return.
- The four Work and three Landscape card geometry, Geist styling, warm tokens, and native Figma SVG dimensions were already close. The existing `ModuleAsset` names correspond to seven present, nonempty card assets; browser geometry checks passed. Hub counts in the Figma examples are not hard-coded into the live page. The Engagement card remains Outreach-only; no Reports or Meetings tabs or fake metrics were added.
- Team rows now show data-derived 32px initials, use the existing `SelectInput` wrapper around `@capiro/ui/select` for role changes, use the design's compact columns and badge widths, and display joined dates as `MMM D, YYYY`. The table and mutation workflow remain the existing shared components. A focused browser case changed a non-self member's role, checked the exact `settings.team.setRole` request, and observed the reloaded role.
- Profiles search now occupies the design's 240px toolbar slot rather than covering its tabs. Populated rows show initials or the provided logo, status dots, and `MMM YYYY` added dates. The owner column now reads the existing tenant-scoped `GET /client-account-owners` map via `settings.profiles.accountOwners` and shows a 24px account-owner avatar with an accessible name; unassigned, archived, loading, and failed reads retain “—”. The review screenshot uses nine synthetic client/owner records **only in a test**; the application still reads actual backend responses and does not inject sample records.
- The connected Microsoft card now uses the live `settings.integrations.list` identity/status/last-sync fields. The Figma “Realtime” button invokes the pinned backend's `POST /engagement/integrations/microsoft/:connectionId/subscriptions` operation only for a connected Microsoft account, with the authenticated transport, busy-state gating, validated `{ configured: true }` receipt, and normal service error handling. The response projection drops subscription details, including secret client state. Its connected screenshot and operation test use synthetic responses only inside Playwright.
- The Integrations badges reuse `SettingsBadge` with the exact local Figma assets `settings-integrations-imgEllipse.svg` and `settings-integrations-imgEllipse1.svg`. Both files are nonempty 5 × 5 SVGs, and the connected browser case confirms each renders at 5 × 5 in its intended badge slot.
- Billing now shows `slots × pricePerSlotUsd` as “Capacity list price per month,” which is a base price, not a promised next charge. It continues to use the authorized hosted provider for payment, invoice, and cancellation actions.
- Settings presentation rules specific to Team and Profiles are isolated in `settings-record-tables.module.css`, and Integrations card rules in `settings-integrations.module.css`; existing shared controls remain in `settings-controls.module.css` (354 nonblank lines after the split). No shared shell, token, lockfile, Memory, Meri, or Portfolio source was changed.

## Shared shell and library proposals for the visual owner

1. The Figma header is a 64px content band and a 1px divider, totaling 65px. `shared/shell/module-shell.module.css` currently has a 65px border-box header with a 2px bottom border. Make its content band 64px and divider 1px while preserving the 65px overall height. The Settings body offset should stay `calc(100dvh - 65px)`. The Figma header also has a sidebar toggle at x184 absent from the current Modules/Settings capture. Make the control functional if added.
2. The 232px Modules rail matches width, but its bottom Settings link falls below the 1440 × 1040 capture when hub content makes the document taller. The Figma rail keeps Settings at the viewport bottom (about y1004). Give the rail viewport-bounded scrolling/positioning so the link stays reachable without hiding module links.
3. Standard Settings Figma frames show Account, Workspace, and Intelligence in the rail; the current Capiro-admin fixture also shows the Capiro HQ group on those pages. Resolve where authorized HQ navigation should live before suppressing it, so the visual change does not strand HQ routes.
4. `DataTable` accepts only a string column label. The Figma Team/Profiles action column has a blank visible header; an optional visually hidden accessible label in the adopted table wrapper would permit that without losing column accessibility. The local pages keep the visible “Actions” label for now.

## Remaining design and contract gaps for Neo

- `/modules`: Figma's seven card metrics and “14 client profiles” are examples. The hub's available-profile count is already a real `clients.list` count. A full-firm metric for each module requires a scoped aggregate contract and loading/empty/error designs: Outreach list results are user-owned and capped at 100 (`apps/api/src/engagement/engagement.service.ts:2609`), Research Portfolio results have no total (`shared/capiro/operations/research-portfolios.ts:35`), and `/intelligence/portfolio-summary` reports different Portfolio statistics. The user-directed Outreach-only Engagement scope overrides the design's Reports and Meetings tabs.
- `/settings/team`: Figma Pending shows “Invited by Jordan Clayton”; `GET /tenant-admin/team/invitations` projects no inviter (`apps/api/src/tenant-admin/tenant-admin.service.ts:198`). Current data can show email, role, sent, expiration, and resend. Neo needs an authorized inviter field and a pending/empty design; the test fixture has no invitation.
- `/settings/billing`: Figma depicts a specific 20-slot, 12-month plan with a 30-day cancellation window, ACH last four digits, invoice email, and invoice rows. The pinned `GET /billing/state` and `GET /billing/summary` expose capacity, list unit price, usage, status, and current period end only (`apps/api/src/billing/billing.controller.ts:20`). Hosted `POST /billing/portal` handles payment, invoices, and cancellation; it does not provide those rows to this route. Neo needs frontend-safe terms/payment/invoice contracts and current-state, trial, past-due, canceled, and unavailable designs before exact Billing parity is possible.
