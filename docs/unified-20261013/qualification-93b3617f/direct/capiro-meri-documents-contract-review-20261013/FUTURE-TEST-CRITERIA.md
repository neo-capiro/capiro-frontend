# Bounded future document controls

These are criteria for the later separate worktree, not tests run or implementations authorized by this packet. Use the eventual published receiver and public synthetic fixtures; never private backend test helpers or fabricated authority.

1. **Public boundary:** exact create/revise/inspect outer bodies and canonical DOCX request types; reject extra identity/scope/grant/path/credential fields, unsupported operations/PDF, invalid IDs and foreign/malformed success. Receiver controls must include strict enum/status/error combinations and all nested canonical correlations without frontend duplicate validators. Missing enablement/session/client causes zero document calls.
2. **Explicit connection and dispatch:** no session or document request on mount/navigation; deliberate connection uses the existing session endpoint and captured client hint. Native/tool credentials cannot replace an opaque session. Session result must match the selected client; no UI chooses actor/run/fence/grants. Setting client loading pauses new work and release, while unavailable/revoked access clears protected material.
3. **Interrupted writes:** install the delivery/attempt fence before any reentrant observer or network dispatch. Double submit sends one request. Held create/revise during close/Back, expiry, caller abort, timeout, malformed acknowledgement and lost connection cannot become success or rollback. UNKNOWN/RESULT_NOT_RELEASED remain fenced through same-cache reopen; no automatic retry, new delivery allocation, regeneration or refund. Canonical cache clear must not be repopulated by old settlement; replacement query generations cannot be overwritten.
4. **Draft ownership:** lock pending submitted fields or preserve submitted versus later draft revisions explicitly. A matching old acknowledgement must never silently discard subsequent local edits. Changing base version requires an explicit deliberate selection and replacement draft; refresh does not erase an open unsaved draft. No draft/credential/private version content in QueryCache, localStorage, URLs or logs.
5. **Immutable version correlation:** create adopts only its canonical correlated version/inspection/execution. Revision returns a different version ID with the exact displayed base as parent and exact intended request/content bindings. Foreign-client/run/version, wrong parent, duplicate/stale acknowledgement and stale-parent refusal cannot replace displayed state. Original version remains selectable only if actually known and inspected under current authority; no invented latest/list endpoint. If acknowledgement is lost and version ID is unknown, show unresolved state rather than synthesize a record.
6. **Read effects and revocation:** inspect/download use the exact chosen version ID and perform no document creation. A denial while reading either current or older versions clears obsolete details and disables download; a late formerly valid read cannot publish after user/session/org/client/context replacement. Read failure is READ_UNAVAILABLE or the exact published release disposition, not evidence of remote deletion or rollback.
7. **Binary integrity:** same-origin fixed POST, no redirects/retries, finite byte budget and deadline; Content-Length preflight and incremental overflow; malformed MIME/filename/disposition; advertised/actual byte length and expected hash mismatch; error JSON masquerading as a DOCX; aborted/parked body and late response acquisition. Do not offer a Blob/download until current authority and published exact version/hash/length/MIME/filename all match. Revoke object URLs on replacement/disposal; no stale object URL after revocation. Use a real small public DOCX byte fixture for integrity tests, without pretending to qualify Office rendering.
8. **Navigation/accessibility:** existing desktop Files and mobile Files reach `/meri/files` with the verified client hint; Conversations/Actions/Files have exactly one current destination. Keyboard focus, logical form labels, pending/error live regions, zero clipped controls at narrow width and no false library counts. Back/Forward must not dispatch or bypass an uncertainty fence. Public route smoke and explicit unavailable state must work with no backend.
9. **Qualification separation:** exact package tar/hash/export checks; focused unit and browser evidence; existing action/session/Portfolio/Modules assertions preserved; boundary/size review, full required gates and approved design comparison after integration. Native identity/RLS/current-run/storage/download and production activation remain separate authorized checks.
