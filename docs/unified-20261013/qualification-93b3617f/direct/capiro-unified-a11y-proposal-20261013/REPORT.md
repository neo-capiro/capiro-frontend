## Proposed patches

Apply `01-confirmed-product.patch`, then `02-fixture-landmarks.patch`, then the independently reviewable `03-incomplete-semantic-followup.patch`, or apply `ALL-PROPOSED.patch` once. Do not apply both forms. `candidate/` contains final proposed bytes only; it is not a serving/build worktree. `SOURCE-PINS.json` binds each original Git blob/SHA256 and proposed SHA256.

1. **Light muted text** — `apps/web/src/app/globals.css:6`: change only `--muted-foreground` from `#78716c` to `#756e69`. All 70 contrast node instances across the six audits report foreground `#78716c` on `#f5f5f4`. Arithmetic increases contrast from 4.3977:1 to 4.5934:1 (5.0111:1 on white), a three-step decrease per RGB channel. This clears the 4.5 threshold with some margin while retaining the hue and existing design hierarchy. The Portfolio dark override `#aaa29c` and every dark background remain byte-for-byte unchanged. The token is shared, so root should retain visual coverage beyond the three audited pages; this proposal is not evidence that every surface passes. Threshold comparisons must use the unrounded ratio. [WCAG contrast guidance](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

2. **Meri landmark** — `apps/web/src/shared/shell/ProductShell.tsx:34`: keep the outer footer and its class; move `role="note"` to a new inner div surrounding the identical existing conditional. The footer regains its implicit contentinfo landmark, while the note role, both original messages and visibility remain. There are no new requests, state or event handlers. `note` is not an allowed overriding role on this footer. [ARIA in HTML](https://www.w3.org/TR/html-aria/)

3. **Portfolio card semantics** — `apps/web/src/features/portfolio/index/ProfileResults.tsx:85` and matching CSS: use H2 with the exact prior H3 typography. Keep `Open ${client.name}` unchanged. Make the linked client name the heading content, and retain sector/location as visible, ordinary sibling text referenced by `aria-describedby` with React `useId`. The sector is **not** `aria-hidden`, visually hidden or removed; it remains available in reading order and as the link description. Hide only the redundant logo/initials, whose client name is already visible. A small stretched-link pseudo-element preserves the original card-top pointer target, while the status/owner area remains outside that target. Existing global keyboard focus styling remains in force; the new link carries the prior ellipsis behavior, leaving its H2 ancestor unclipped. Root must verify pointer hit area, long names and visible focus after application. Separating contextual description from the visible link label preserves both information and the exact meaningful test name. [WCAG label-in-name guidance](https://www.w3.org/WAI/WCAG22/Understanding/label-in-name.html)

4. **Fixture-only landmark** — `apps/web/test/browser/main.tsx:79,146`: replace each root `.test-notice` paragraph with a named `aside`, retaining exact visible text and CSS class. This covers the captured Modules notice and its same-owner public-form equivalent. It is a complementary landmark called `Local test fixture`, distinct from the product navigation. No hiding, rule exclusion, opacity or text removal is proposed. The Modules region failure is a harness defect, not proof of a missing production notice.

5. **Incomplete semantic follow-up** — the Meri suggestions collection gains `role="group"` while retaining `Draft suggestions`; the symbolic owner avatar gains `role="img"` while retaining its exact owner name/fallback; supplementary profile-status and shown-alert-count annotations gain `role="note"` while retaining labels/text. These are static annotations, not live regions. In particular `getByLabel("N shown alerts")` remains meaningful and unchanged; no original tests are weakened to get a green result. Named notes and images support author-provided names; a generic span/div does not reliably expose these names. These proposed roles require rendered accessibility-tree review, and are supplied separately so root can assess the semantics without conflating them with axe's confirmed violations. [WAI-ARIA role definitions](https://www.w3.org/TR/wai-aria-1.2/#note)

The screenshots are viewport-only: the Portfolio card and Meri footer are below the captured phone crop. Their full-document axe findings are still valid baseline evidence, but the images do not prove their layout, visibility when scrolled, or screen-reader output. They repeat the desktop semantic concerns and Portfolio gradient/short-text cases. The desktop-only Meri New conversation gradient is absent when the sidebar is hidden on phone. The Modules decorative arrow contrast review is desktop-only; Open Engagement remains incomplete at both sizes.

This supports retaining those colors but is **not rendered manual verification**: computed inheritance, compositing and overlays still need inspection. Short `1` counters are meaningful text and must stay visible/readable. The Modules `→` is already decorative with `aria-hidden`; leave it intact and verify its neighboring link name and visual affordance. The fixture account `T`/`Test account` name result is indeterminate, not a confirmed mismatch; retain the meaningful exact account name and manually review the symbolic avatar. No additional `aria-hidden` or rule suppression is proposed to make incomplete checks disappear.
