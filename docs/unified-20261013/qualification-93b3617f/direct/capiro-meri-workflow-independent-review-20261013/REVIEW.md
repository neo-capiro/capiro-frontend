## State, handles and authority

The presentation port carries recommendation selection, draft and proposal as opaque objects. The controller preserves their exact identity through draft/prepare/execute, copies and freezes the displayed scalar fields, and never serializes, examines or rebuilds those handles. Editing a reviewed draft invalidates its prior handle. The port offers no approval method, credential, actor/tenant/client authority field, HTTP operation or private backend import. Local view types are presentation models, not a competing wire DTO or validator.

Preparation only produces a pending proposal. Execution requires a deliberate action and passes the same immutable proposal handle; an approval-pending response does not produce an observed result. Deliberate replay is allowed only while that local state remains admitted. Observed success and observed failure are distinct. Unknown, indeterminate, result-withheld, stored-withheld, metadata-not-stored and read-unavailable states withhold success and fence further requests. Lost access additionally clears old recommendations, selected inputs, draft and proposal data. Fixed error copy avoids raw exception leakage and preserves the metadata-only meaning of NOT_STORED.

The controller sets busy synchronously before invoking the port, so duplicate clicks cannot dispatch a second concurrent operation. Disposal aborts local observation, advances a generation, resets local display and rejects late settlements even after reattachment. This is not durable cancellation, a database rollback or a cross-remount/reload idempotency guarantee. The feature currently has no host consumer or active route. `lifetimeKey` and port identity can replace its local controller; a real host must still bind actor/session/tenant/client replacement, current authorization and durable recovery to canonical owners. A host must not interpret creating a new controller after uncertainty as permission to repeat an effect.

The missing governed public action-result parser remains a backend dependency. Before activation, the authenticated adapter must validate wire results/lineage with that public package, preserve exact validated handles, normalize local date input under the canonical task contract and map content-free dispositions. Public frozen UIEvent validation and projection stay unchanged. The supplied handoff's separate fixture approval cannot become a browser approval endpoint or authority grant.
