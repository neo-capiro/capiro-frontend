## Source and responsibility review

The staged intent contains only source/destination IDs, snapshot hash and original state version; no editor plaintext or upload/provider payload is persisted. The same encrypted shared session journal used by Quicklog and prospect recovery owns durability. A competing view cannot substitute a new pending intent. Explicit recovery freshly reads Core identity, current draft, the selected saved revision and destination. New staging rejects non-active sessions; original receipt recovery may consult a later/archived session without changing the original applied version. Storage or authority refusal clears review and holds dispatch. A malformed or conflict receipt leaves the original intent pending.

- StagingSelection: This renderer owns one explicit saved-revision and existing-session staging review. Source/session query selection, compatibility disclosure, retained-intent presentation, review acknowledgement and receipt link describe the same bounded interaction. The fixed gateway owns transport schemas, staging-model owns binding checks, useNewsletterStaging owns dispatch/recovery, and shared/session/recovery owns persistence. It neither creates sessions nor generates or sends content; no independent domain responsibility is hidden in the view.
- NewsletterWorkflow: The established Newsletter builder retains its template/editor/preview/comment/save behavior. Its former unavailable staging placeholder now delegates to the cohesive NewsletterStaging component. No wire contract, persistence or write lifecycle was added to the builder. The existing panel and actions remain its presentation responsibility.
- useNewsletterStaging: This hook owns one original staging intent from explicit submission through validated receipt acknowledgement. It composes existing durable recovery and fixed transport APIs with feature-specific source/destination/provenance checks. Preflight, same-key dispatch, uncertain-result hold and explicit acknowledgement must preserve one original lineage; splitting flags across unrelated hooks would obscure that invariant. No content generation, sender mutation or delivery is performed.
