### Quick Log and storage rules

Core commits activity/details and durable follow-up intent in one local transaction. Remote Planner task creation remains an idempotent saga with pending/needs-attention/recovery states. Store the request key before the POST; recover with the existing lookup/resume owner rather than another create. A custom follow-up title and strategy-step binding remain unsupported. The generic Planner payload prevents copying protected client details into a task whose personal ACL does not continuously follow the client wall. Required config: HTTPS `QUICK_LOG_PLANNER_ORIGIN`, plus the deployed Planner task-create-command owner/expected-scope preconditions. PR94's added details require no new migration.

Storage reports **registered attachment usage against 10 GiB per client** with `enforcement: report_only`. Hidden/superseded/retained lifecycle registry rows count. Missing/invalid size metadata or unsafe totals return unavailable with null totals; errors do not become zero. The registry excludes unconfirmed/orphaned objects and noncurrent physical S3 versions. This is not physical storage billing or upload enforcement.
