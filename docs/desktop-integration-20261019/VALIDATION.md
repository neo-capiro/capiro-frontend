## Why inherited checks were corrected

1. The native preferences route intentionally uses `session.getToken()` for a session-bearing native token, introduced by `95a0d908c64e34e50a43dab0bda79dc50682ad41`. The original route and stale test were byte-identical to PR101 before this lane. Only the assertion changed; it still rejects template arguments and checks preview containment. Authentication code was not altered.
2. Portfolio Clients stage intentionally does not fetch business-development data, established by `a8c2165f003d1d7bef0247e57fed925b78efcba5`. The test now expects unavailable totals until All is selected, then asserts the source-backed 14 total / 8 clients / 6 prospects. Production behavior was preserved.
3. Engagement's accepted heading is **Engagement** with Outreach as its sole working surface. The inherited **Engagement Manager** expectation was corrected. Reports/expanded tabs were not restored.
4. Outreach list inputs already include a one-year UTC range and `deleted:false` from `b57072a5e3bb3e2028e64ce55bca9cf576f6f014`. The test freezes Date to 8 October 2026 and asserts the exact query, including the end-exclusive 9 October boundary. Receipt mismatch concealment, no effects and matching-read recovery remain asserted.
5. Core's Client schema at `b841544adef13ab5f129339cf7c4d813dd67bad4` stores lifecycle `status` default `active`, separately from profile `profileStatus` default `ACTIVE`. The current-project test's local client fixture was corrected. Production scope guards remain unchanged. The negative project test now proves each bootstrap response was read before rejecting missing, foreign, archived or duplicate targets with zero task reads; it no longer passes before reaching that boundary.
