| Immutable association and exact receipt | `admission.ts` compares full source identity and tenant/prospect/client/draft/document/request/operation. `versionId` equals the request UUID. Actor compares to `scope.actor.ownerId`, populated from `me.user.clerkUserId`; DB user ID remains an additional journal/authority identity, not the receipt actor. Server hashes remain opaque; the feature does not reconstruct private hashes. |
| Current body after historical receipt | `transactions.ts` reads fresh detail plus an independently fresh scope-checked state, requires selected membership/source and equal state hashes, and never renders receipt content as current. Reconciliation acknowledges the retained request only after those reads succeed. A replay can legitimately refer to an older version than the newly read current body. |
| Exact retry and cross-tab serialization | `useBriefCopyCommand.perform` takes the canonical execution lock and reads the journal again inside that lock. Synchronous `busy` protects one mounted instance. Reservation retains the exact UUID and complete command; update validation forbids changing unresolved input. Retry explicitly reuses it, including its older CAS hash. No effect runs on hydration. Shared journal storage/locking stays canonical. |
| Refusal versus uncertainty | Only a qualified `WORKSPACE_BRIEF_STATE_CONFLICT` marks known no-write refusal. Explicit review rechecks current authority and fresh state before the canonical retirement helper; proposed body is carried into a new local draft and another explicit save allocates a new UUID. All other errors retain the original command. A saved receipt with failed fresh reads is retained and recovered by read/reconciliation without a second POST. |
| Identity/navigation lifetime | The route remains inside the existing ApplicationBoundary and canonical Capiro data provider; no new auth, client, transport or session escape exists. Workflow keys include scope/source/document, retained journal keys include tenant/DB user/Clerk actor/parent/target, and guards/AbortSignal are checked around awaited admissions. Parent/client/Clerk mismatches block dispatch. Transport abort is not described as durable cancellation. |
| Bound-tab legacy restrictions | Bound tabs are exposed through exact copied-tab links and excluded from legacy section flattening, ordinary content rendering, and newsletter initialization/PATCH selection. The copied editor uses only atomic save; history is read-only and exposes no whole-draft restore. Root schemas preserve association/body. Backend enforcement remains required for all clients and concurrent changes. |
