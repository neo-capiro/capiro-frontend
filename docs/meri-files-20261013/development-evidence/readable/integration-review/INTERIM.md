## Reviewed boundaries

- Independent literal action/document opt-ins remain closed by default. Document activation additionally requires exactly `create_word` or `create_excel` in server configuration. Either enabled workflow can use the original opaque-session bootstrap; enabling documents does not enable action query/draft/prepare/execute. Production page composition, unlike the explicit browser fixture, takes no family from URL/browser input.
- Only create/revise/inspect/download POST routes are allocated. Exact paths, same-origin requests, no query strings/compression, valid configuration and signed-in native session are required before forwarding. The native Clerk `capiro` token is used only for session bootstrap; document operations forward only the opaque session bearer, JSON content type and request bytes, with credentials omitted and redirects refused. No approval/list/upload/delete/reconciliation endpoint is invented.
- Create/revise request admission uses the public receiver and checks configured family. Inspect/download only contain an immutable version ID, so the proxy cannot infer family; trusted native mount authority plus received format/current-view checks remain required. One deployment binds one family, preserving Word DOCX/TXT and a separately configured XLSX flow.
- Binary forwarding preserves bytes and verification headers, strips cookies/location/private headers, and does not fabricate missing verification metadata. Request acquisition is bounded to 2 MiB; JSON/binary responses to 16 MiB. The shared deadline covers body acquisition, and late/unconsumed bodies are cancelled. Browser download receiving performs the actual branded-version/header/count/SHA/EOF check before bytes are exposed.
- The opaque connection extraction preserves the original Action host lifecycle. Canonical ApplicationBoundary replaces user/session/organization/client scopes. Connection disposal aborts the transport, erases the private bearer, disposes the port and drops selected metadata. A current-client pause prevents new operations and publication; explicit reconnect performs no document operation itself.
- A distinct document journal writes pending state synchronously before the first asynchronous hash. Exact cache generation, current lifetime and pending attempt ownership are checked after hashing, before dispatch and after settlement. Cache clearing cannot be repopulated by old owners. Unknown/result-withheld outcomes survive navigation and do not become resolved after an explicit read. No automatic repeat delivery exists. Only fingerprints, attempt ID and disposition enter the journal, with frozen snapshots and disabled query structural sharing.
- The adapter retains real receiver brands behind opaque handles; it checks current tenant/actor/conversation/run/client, configured family, known immutable version consistency and exact revision artifact/parent lineage. It does not equate historical attempt/worker/fence metadata with the current executor. Download request/version correlation is checked explicitly. The final lint adjustment from rest-destructuring to explicit request/base projection retains the same intent for the strict admitted create/revise envelopes and excludes delivery ID.
- Feature state holds local draft/selection and verified Blob URLs only. It never owns session or approval authority, a second wire validator, or native artifact generation. Native Office opening/rendering/recalculation and backend activation are explicitly unqualified. Public-schema synthetic DOCX/XLSX fixture receipts are not native file-generation evidence.
