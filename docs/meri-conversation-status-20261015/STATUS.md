## What is implemented

The normal [`/meri` route](https://github.com/neo-capiro/capiro-frontend/blob/4e1421054df0d32c564f7c9bc75cbd5e5366b428/apps/web/src/app/meri/page.tsx) composes `RequireSession` and [`MeriHome`](https://github.com/neo-capiro/capiro-frontend/blob/4e1421054df0d32c564f7c9bc75cbd5e5366b428/apps/web/src/features/meri/MeriHome.tsx). The home reads canonical Core identity/current client and mounts [`MeriConversationHost`](https://github.com/neo-capiro/capiro-frontend/blob/4e1421054df0d32c564f7c9bc75cbd5e5366b428/apps/web/src/features/meri/conversation/MeriConversationHost.tsx), which composes the existing [session controller/public client](https://github.com/neo-capiro/capiro-frontend/blob/4e1421054df0d32c564f7c9bc75cbd5e5366b428/apps/web/src/shared/meri-conversations/host-controller.ts). It does not replace backend authority with a selected-client hint.

[`MeriConversationView`](https://github.com/neo-capiro/capiro-frontend/blob/4e1421054df0d32c564f7c9bc75cbd5e5366b428/apps/web/src/features/meri/conversation/MeriConversationView.tsx) offers explicit connection, current transcript/history paging, initial submit/same-request retry, cancellation, observation and reconnect. Connection is rendered by the host; the connected view renders the remaining controls. Disposing the view stops observation, not the durable run. SDK-admitted events feed the transcript; no sample response replaces a failed service operation. The [query-cache journal](https://github.com/neo-capiro/capiro-frontend/blob/4e1421054df0d32c564f7c9bc75cbd5e5366b428/apps/web/src/shared/meri-conversations/query-journal.ts) retains command uncertainty and last observed selectors within the canonical account/client/run scope across navigation. It is not durable recovery across a browser restart.

The [configuration owner](https://github.com/neo-capiro/capiro-frontend/blob/4e1421054df0d32c564f7c9bc75cbd5e5366b428/apps/web/src/shared/meri-actions/connection-config.ts) defaults conversations closed. Validated auth/configuration, an approved HTTPS control origin and explicit `MERI_CONVERSATION_WORKFLOW_ENABLED=true` are prerequisites, not qualification. The [fixed proxy input boundary](https://github.com/neo-capiro/capiro-frontend/blob/4e1421054df0d32c564f7c9bc75cbd5e5366b428/apps/web/src/shared/meri-conversations/input.ts) admits the five published conversation operations only. Neither listing nor a new-turn operation is inferred from history, subscribe or submit.

The polished [`MeriRunWorkspace`](https://github.com/neo-capiro/capiro-frontend/blob/4e1421054df0d32c564f7c9bc75cbd5e5366b428/apps/web/src/features/meri/workspace/MeriRunWorkspace.tsx) explicitly says “Sample research workspace” and “Disconnected sample.” Its caller is [`RunActivityFixture`](https://github.com/neo-capiro/capiro-frontend/blob/4e1421054df0d32c564f7c9bc75cbd5e5366b428/apps/web/src/features/meri/fixtures/RunActivityFixture.tsx); it is not imported by the normal host. A polished fixture does not establish a working activity, approval or artifact workspace.

## Contracts needed before implementing missing controls

These are acceptance requirements for owner-published contracts, not proposed endpoints or DTOs. The Meri contract/runtime owner must supply exact versioned public exports and producing source pins; the frontend extends the existing guarded client and fixed proxy only after allocation/review.

| Missing control                           | Required runtime contract                                                                                                                                                                                                                                                                                                                                                                                                 | Frontend behavior after allocation                                                                                                                                                                                                                                                                               |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Recent conversations (`MERI-D01`)         | Discovery under current tenant/native actor/client authority; permitted metadata and safe redaction; stable ordering and cursor/coverage semantics; empty versus unavailable/error; bounded pagination; revocation/deletion behavior; exact selection-to-fresh-session rebinding. A browser-selected conversation ID grants no authority.                                                                                 | List, loading/empty/error/retry and explicit next-page controls; keyboard selection; clear old content on scope replacement; reject late list/session results; load only admitted history for the selected session. No local synthetic “recent” catalogue.                                                       |
| New conversation / next turn (`MERI-D02`) | Explicit distinction between creation and continuation, allowed active/terminal transitions, stable request identity/idempotency, lost-ACK reconciliation, exact conversation/run/source binding and authoritative session replacement/expiry. Define what happens to an existing observed or uncertain command and how current history spans turns. Submit's present session-selected run cannot be silently repurposed. | Explicit controls only; preserve pending/unknown input and its original identity. Never unlock a composer by clearing a journal or mint a new UUID after unknown delivery. Dispose old observation on an admitted replacement without implicitly cancelling work; preserve retry/reopen and fresh authorization. |
| Real run/activity workspace (`MERI-D03`)  | Exact admitted lifecycle/activity projections and any artifact/approval operations, their current visibility, pagination/completeness and allowed actions. Existing event display is not authority to approve or execute.                                                                                                                                                                                                 | Reuse adopted transcript/composer/activity presentation where its data contract fits; disclose missing data/actions rather than mounting fixture events or inventing counts.                                                                                                                                     |
