# Meri PR60 receiving boundary

Read-only review of Meri `a2aef4a5fcd3c19cec974dc62b69222836d71b3e`, tree `c9fe3ebb35213af65a70c01563855dfe08ed2606`. The existing frontend public contracts 0.1.2 tar has **19 of 19 byte-exact members** at that source; current document/action controls retain their established interface. This is source compatibility, not native qualification.

PR60 adds the canonical backend conversation mount and durable event lifecycle. Its README explicitly leaves frontend integration and a versioned public request API as separate work. Conversation authority comes from the current opaque session. Submit, history, cancellation and event subscription are distinct operations; ending a subscription does not cancel or complete a run. Native persistence, Temporal/worker activation and the broader lifecycle remain open with their existing owners.

The concrete receiving gap is in `packages/meri-client/src/guarded-transport.ts`: the existing `createMeriChat` sends a `view.subscribe` command and uses upstream AI SDK 7.0.137 GET reconnect at `/{chatId}/stream` with `x-meri-resume-sequence`. PR60 accepts only POST `/api/conversations/events` with `{after?,limit?}`; its strict request validator rejects the existing command body, and its mount rejects GET. Merely pointing the current transport at the new URL would fail. The event payload remains the existing transient `data-meri-event`, so the public event guard, projection and adopted SDK remain reusable.

The application also has no enabled conversation host for ordinary prompt submit, authenticated history/cursor recovery or explicit run cancellation. Its unavailable Send action remains truthful. The next bounded integration requires the Meri owner to publish the versioned request/response receiving surface and current session capability contract, then root can adapt the existing transport through that public interface, compose canonical session disposal and build UI controls with exact replay, current authority, interruption and cancellation controls. No private backend DTO, worker implementation, parallel chat loop or guessed live endpoint was copied.

This review does not expand the current Portfolio/current-read/Meri-theme repair batch or authorize activation. PR60 owner test reports were not rerun by the frontend owner; no database, worker, provider or paid model action occurred.
