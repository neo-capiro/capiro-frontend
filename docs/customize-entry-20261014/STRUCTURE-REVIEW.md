# Bounded responsibility review

`PortfolioIndex` already composes the current catalog, URL-based presentation filters and the existing Customize entry/exit. Its changed branch now displays the existing `PortfolioProfiles` for the complete current catalog during customization, including when the ordinary filter has zero matches. It keeps the exact URL and suspends local filters/navigation; finishing restores the previous presentation and trigger focus. Loading, failed and empty catalogs expose a local exit. This is the same presentation-session responsibility, with no backend call or authorization implementation added.

`PortfolioProfiles` remains the sole layout-hook consumer within the index. Its lookup uses the full catalog while customizing, so filtered records cannot become a saved subset or blank cards. The existing layout editor continues owning its draft, pointer/keyboard movement, cancellation, save/conflict/unknown controls and announcements. The hook, contract, transport and current actor/catalog/version checks are byte-unchanged. The root session boundary still owns replacement and cancellation.

`IndexOwnerFilter` accepts an optional presentation-disabled state. `IndexNavigation` makes its existing region inert during customization, preventing its controls/links from discarding the local editing session. The stylesheet adds only the inactive region's opacity; no asset, geometry, token or global style is changed. Both components retain their existing defaults outside customization. Search uses its native disabled state while editing.

The size guard correctly flags the changed 270-nonblank-line `PortfolioIndex` function and the existing 493-line stylesheet. Their exact fingerprints are reviewed in the canonical registry. Splitting the composition solely to pass a line count would not isolate a new domain; no new workflow engine, cache or persistence concern has been added. Existing unreviewed findings stay visible, and guards/tests are unchanged.

The four new baseline failures reproduce no editor/unavailable feedback from ordinary list/sorted/filtered views. Current browser checks exercise the actual index, full-catalog save rather than a filtered subset, retained query/view, cancellation, keyboard focus, unavailable ordering and empty/failed catalog exit. Existing layout tests still own conflict/reconciliation/authority behavior. Synthetic interaction checks do not establish native persistence or backend authorization.
