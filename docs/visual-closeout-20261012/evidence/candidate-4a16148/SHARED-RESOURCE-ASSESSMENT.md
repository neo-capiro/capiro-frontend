## Further consolidation worth evaluating separately

- Presentation wrappers and tokens: Module `Field` / `Badge` / `Modal` conventions and Portfolio field/status/dialog styles overlap. Both dialog wrappers already use the same Radix-based package primitive, but Portfolio adds nested Escape, overlay dismissal and focus-return safeguards. A shared wrapper must preserve those behaviors and product-specific geometry. Duplicate base resets, `sr-only` / `srOnly` helpers and Newsreader declarations are concrete style-inventory candidates; harmonization requires cross-mode light/dark and portal checks.
- Browser download mechanics: `features/modules/workspace/prospects/ProspectDraftExport.tsx` and `features/modules/strategies/StrategyExport.tsx` repeat the same object-URL, temporary anchor and delayed revoke sequence. A small presentation-side download utility is plausible. Preserve each feature's preflight, validated filename, cancellation and receipt handling. Portfolio's `client-profile/export/actions.ts` has additional explicit guards and immediate cleanup; do not merge those semantics merely because it also creates a URL.
- Repeated field/error/empty-state presentation can be inventoried into the existing UI package or shared adapters. Do not conflate this with consolidating queries or schemas: Modules' mutation hook deliberately refuses automatic write retries, Portfolio uses its own query and receipt machinery, and Meri's guarded stream projection has another lifecycle.

No consolidation edits are included in this seven-repair candidate. Date formatting, scope checks and operation schemas were not declared duplicates merely because their code looks similar.
