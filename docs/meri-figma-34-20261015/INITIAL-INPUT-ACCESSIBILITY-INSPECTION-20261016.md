# Initial-input source accessibility inspection

This is source inspection and test authoring only. No browser, visual render, assistive technology, live credential or native service was used. Earlier incomplete manual-accessibility and untested-state records remain open. The genuine0.1.8 package and coherent browser checkpoint are still required.

The canonical adopted `PromptInputTextarea` already handles composition before its Enter submission and respects an external prevented event. The Meri wrapper previously blocked every plain Enter when sending was unavailable, including native composition commit; it also left `canSend` true during a running turn when only Stop was rendered. The wrapper now excludes composing/keyCode229 events from its blocked-Enter guard and includes the running state in Send availability. This prevents a running draft from reaching the upstream form reset. No adopted upstream source was edited.

Textarea and current Send/Stop action now share a `useId`-backed help description, avoiding the fixed `send-help` ID if multiple composers are rendered. The description retains the actual blocked-send reason and adds the running/blocked-stop explanation. Draft input stays labelled and editable while commands are pending. Six authored desktop cases include repeated Enter during held admission, accessible description linkage, Enter while running, native composition commit without preventDefault, session expiry, lost ACK/navigation and positive stored-input recovery. All six are **UNRUN**.

The new initial action proposes an input to the real durable allocator; editable text and enabled Send do not establish unsent state or permission. Known saved/reserved/retained turns continue to block a new initial proposal. Closed allocation errors are announced through the existing command error/status region, while exact retry uses the retained request. Source ownership still separates receipt correlation from display history, so an empty synthetic tail cannot erase accessible transcript content.

Unresolved manual checks include keyboard focus when Send becomes Stop or Retry appears, platform-specific IME/keyCode229 event ordering through the adopted component, announcement order and duplication in nested live/alert regions, screen-reader transcript position while saved pages arrive, zoom/reflow, contrast and target sizes, and repeated-flow behavior with actual production CSS and session boundaries. No axe, keyboard, screen-reader or visual PASS is inferred from this inspection. Existing Settings and non-Meri accessibility scope is unchanged.
