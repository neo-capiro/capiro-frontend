## Implementation outline

1. Register only `POST /clients/:clientId/objectives/:objectiveId/generation/strategy-commands` as a Core Capiro operation with the exact closed schema version 2 wrapper. Reuse the existing PR #53 receipt and seven Strategy types. Bind the v2 selection echo and command receipt to the saved wrapper and pre-command observation.
2. Take a fresh authenticated Core identity, selected-client, Objective-list, and governed generation read before a **new** command. Require the current saved Objective to be ready and its revision ID/version to equal the requested ready source, with control version zero and no current consent or accounted work. These browser checks are a scope fence; Core owns authorization, custody, and atomic reservation.
3. Save the complete wrapper, both distinct UUIDs, and original source observation in the shared encrypted recovery journal before POST. The journal key is tenant, actor, client, and Objective, so a version change cannot silently create a second command. Serialize tabs with the existing command lock. A lost response or 409/503 leaves the command pending. An explicit recovery sends exactly that wrapper; it does not apply new-command CAS or source checks to a prior immutable receipt. A successful verified response is retained and displayed only as consent plus a reserved intake job.
4. Keep the new Objective editor panel behind `governedStrategyIntakeEnabled = false`. The visible legacy generation panel remains mounted until a reviewed serving and preview policy release turns on the governed path. No Strategy output link or completion claim follows from an intake receipt.
