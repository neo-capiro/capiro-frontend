## Source finding and narrow correction

The current frontend `capiro` JWT template was used as the bearer for Meri action-session issuance and conversation history. Meri forwards the action-session credential to Core `/api/clio/application-authority/identity` and `/context`; its membership-backed history path invokes Core identity and membership. Core PR #48 requires a JWT `sid`, `sub`, unexpired `exp`, and a current online Clerk session for these authority endpoints. [Clerk's JWT-template documentation](https://clerk.com/docs/guides/sessions/jwt-templates) states that custom JWTs do not include `sid`, while its [session-token documentation](https://clerk.com/docs/guides/sessions/session-tokens) lists `sid` among the native default claims. This is a source-level admission failure even if Core conversation bootstrap succeeds.

The frontend correction changes only these dot-owned shared API route token providers:

| File                                                             | Exact selection                                                                                                              | Ownership and effect                                                                                                                                                      |
| ---------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `apps/web/src/app/api/action-followthrough/[operation]/route.ts` | `operation === "session"` uses native `auth().getToken()`; other action operations retain `getToken({ template: "capiro" })` | Dot owns the shared gateway source. The session route serves both first-chat and document-only bootstrap. Meri still owns session admission.                              |
| `apps/web/src/app/api/conversations/[...path]/route.ts`          | The native history bearer provider uses `auth().getToken()`                                                                  | Dot owns the shared gateway source. The history proxy forwards this bearer to Meri; ordinary opaque action-session requests continue through their existing route checks. |

The Core `meri.conversation.bootstrap` registered operation, its six-field receipt, and the `capiro` template selection in `/api/capiro/[operation]` remain at PR #60/64 source. Core PR #48's bootstrap uses ordinary tenant middleware, with no demonstrated `sid` requirement on that handler. No Core auth or Meri runtime source is changed here. The selected-client GET source marker remains exact Core `6542f5b089656b6d255465edd464d06c2a0b408f`.
