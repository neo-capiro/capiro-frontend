# Location economic evidence sections

`FacilityEconomicSections` owns only three read-only location-body sections. Props are `{ scope: ProfileEvidenceScope, open: boolean, ids: { economic: string, unemployment: string, workforce: string } }`. Root owns `FacilityDetailDialog`, navigation, representation and other body sections. Canonical `useProfileEconomicFootprint` and `useProfileDistrictEconomicContext` own requests, actor checks and exact receiving schemas; neither is duplicated or edited here. The component calls each hook once and uses each query's `enabled` guard before showing data or loading, including when old cached data is present. A closed body renders nothing. Missing actor/scope and unresolved district are explicit states rather than an indefinitely pending disabled query. Client and district failures remain independent with the existing `QueryState` retry owner.

Current Figma Portfolio 3.4 high-fidelity context was read for [Client economic footprint, 1118:279012](https://www.figma.com/design/mpXWnySldUFzdVna8i69Ki/Capiro-3.4-Portfolio?node-id=1118-279012), [Unemployment, 1118:279051](https://www.figma.com/design/mpXWnySldUFzdVna8i69Ki/Capiro-3.4-Portfolio?node-id=1118-279051), and [Workforce and commuting, 1118:279074](https://www.figma.com/design/mpXWnySldUFzdVna8i69Ki/Capiro-3.4-Portfolio?node-id=1118-279074). Their isolated screenshots were 1×1; the current visible parent [District details Arsenal-1, 1064:159626](https://www.figma.com/design/mpXWnySldUFzdVna8i69Ki/Capiro-3.4-Portfolio?node-id=1064-159626) was therefore read through full design context and its visible screenshot before editing. The card, label, metric and provenance structure uses existing tokens and native CSS. No static asset is present in these three sections; no screenshot is used as a runtime asset. Material source states are rendered from actual receiving types, not the mockup's illustrative numbers.

Location attribution requires `evidence.promotedFacilityId === scope.facilityId`. Same district, client-wide aggregates, other locations, unlinked evidence and facility staff previews are not used to infer site employment, payroll, investment or totals. All explicitly linked records retain their evidence type, value, unit, currency, source verification, independent pending/approved/rejected review state, independent external-use flag, effective-from/to, observation/review/creation timestamps, supporting record/import/row IDs and reported geography. No unverified employee figure becomes a current, actual or verified jobs measure. No records are added together. The read's latest-1,000-client-record limit is visible and is explicitly not a complete reporting-period history. Client-wide `totals` are intentionally not presented as location totals. A lack of returned linked rows is not a claim that no historical evidence exists.

Unemployment consumes only `source === 'acs'` plus the exact returned `unemployment_rate_percent` key. All returned vintages remain visible in received order with dataset, year, boundary Congress, value, unit, margin of error, source record/URL, observation and sync timestamp. Workforce displays actual `lodes` metric rows in the same way. Zero is displayed as zero; null is unavailable, never zero. No latest-year policy, ACS population denominator, commuting total, local-hiring result or unreturned measure is synthesized. Each source's returned annual sync runs retain status, year, boundary, attempt/completion timestamps and row counters, independently of stored metric availability. Missing runs and missing metric rows are separate truthful states. Source diagnostic text is not printed; a returned diagnostic is represented by a generic source-error notice. Response generation time, metric observation, metric sync and source completion remain distinct.

`facility-evidence.module.css` is exclusively owned by this slice. Root may consume its exported `card`, `heading`, `metrics`, `metric`, `value`, `records`, `record`, `rows`, `source` and `state` classes when composing adjacent sections; root should coordinate CSS edits here. No dialog ownership, mutation, auto-preview/import action, backend contract, shared package, HTTP, registry or token is changed. Economic entry/import flows still require the independently requested design and command allocation.
