# Contact message history date

Bounded desktop implementation based on the current Portfolio 3.4 file [Contact message history component set, node 431:41501](https://www.figma.com/design/mpXWnySldUFzdVna8i69Ki/Capiro-3.4-Portfolio?node-id=431-41501), specifically [Ready, node 431:41496](https://www.figma.com/design/mpXWnySldUFzdVna8i69Ki/Capiro-3.4-Portfolio?node-id=431-41496). High-fidelity design context and the initial component-set screenshot were received on 16 October 2026; the 582×195 Ready screenshot was also downloaded and visually inspected before editing. Ready rows show subject, snippet and a muted date/time caption. Empty, Loading, Error and No email are explicit design variants. There are no static assets in the affected rows.

`ContactMail.tsx` remains the owner of the contact-history list. Its local date presenter consumes existing `MailThread.messages` only. For each returned message it uses the existing mail effective-date precedence `sentAt ?? receivedAt ?? createdAt`, then displays the greatest finite instant in that returned projection. Timestamp comparison is numeric, including offsets. It never sorts or mutates the returned messages or threads. The semantic `time` element preserves the chosen source timestamp in `dateTime`; visible text follows the existing local-locale convention, with short month, day, year and time separated by a middle dot. The existing Portfolio `small`/`muted` presentation is reused. Missing or entirely malformed dates show `Date unavailable` rather than the current time or `Invalid Date`.

This is the latest **available returned-message** date, not proof of a complete mailbox or thread history. The existing list is bounded and its detail model explicitly distinguishes its short projection from the full-thread read. The date caption therefore says `Latest available message date` in its title. No new detail request, endpoint, sorting policy, mailbox count, authorization claim, shared schema, transport or dependency is introduced. The existing client/contact keys, error invalidation, query gates, compose/reply gates and selected-thread behavior are unchanged. Current ContactDrawer and TargetDrawer callers are unchanged.

Dedicated rendered cases in `apps/web/tests/contact-mail-date.test.ts` cover unsorted and offset timestamps, source precedence, missing/malformed dates, retained row order/nonmutation and existing empty/no-email/loading/error visibility boundaries. These cases are authored but **UNRUN** pending the coordinator's focused test profile; this new worktree has no installed dependencies. No install, compiler, browser or build was launched by this slice. The installed Next client-boundary documentation was read from the existing PR56 dependency tree; no Next entry or server/client boundary changed. Full visual parity, responsive rendering and interactive regression qualification remain pending the shared browser/build coordinator; this timestamp-only slice does not claim full component parity or mobile qualification.

Exclusive changed paths: `ContactMail.tsx`, the dedicated test above and this document. The shared worktree also contains other owners' changes, which this slice does not stage or commit. Base is PR56 `3ef15d9a8ae6a27a9c2f39ccd923b5e2e07797cd` / tree `fe91d99ea53e982f73fd346c0dcff0f7225597cd`; deployed 9da and published PR56 remain separate.
