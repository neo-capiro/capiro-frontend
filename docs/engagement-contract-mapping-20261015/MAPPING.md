## Permissions, privacy and failure ownership

Trusted tenant/actor come from TenantContextMiddleware, never the client selector. EngagementController requires standard_user or higher through RolesGuard. Prisma withTenant enforces tenant predicates; it is not a per-client authorization proof. [tenant context](https://github.com/neo-capiro/capiro-backend/blob/cd3c51e940f14e1b2a1040b0ffa445e85d68b332/apps/api/src/tenant/tenant-context.middleware.ts#L372), [role guard](https://github.com/neo-capiro/capiro-backend/blob/cd3c51e940f14e1b2a1040b0ffa445e85d68b332/apps/api/src/auth/roles.guard.ts#L18), [Prisma scope](https://github.com/neo-capiro/capiro-backend/blob/cd3c51e940f14e1b2a1040b0ffa445e85d68b332/apps/api/src/prisma/prisma.service.ts#L100).

Actual report reads: stored target rows and ordinary tasks are tenant-scoped; meetings use ownMeetingWhere (creator or owned calendar, nondeleted); mail uses ownMailMessageWhere (owned connection, active messages). Notes/debrief bodies are not read into the report. [report predicates](https://github.com/neo-capiro/capiro-backend/blob/cd3c51e940f14e1b2a1040b0ffa445e85d68b332/apps/api/src/engagement/engagement.service.ts#L5253), [canonical access predicates](https://github.com/neo-capiro/capiro-backend/blob/cd3c51e940f14e1b2a1040b0ffa445e85d68b332/apps/api/src/engagement/engagement-access.helpers.ts#L36). Task rows may contain ordinary descriptions; “private notes/mail excluded” must not imply that every source-derived task description is safe.

The inspected HTTP report/task reads do not apply the per-client memory-wall/current-access predicates present in the **Meri-specific exact reader**. Do not call/copy that reader into this desktop task or claim its guarantees for these HTTP routes. Existing client selector and tenant-wide returned data do not independently prove the retained design's “permitted clients” scope; the backend scope owner must qualify that meaning before expanding an aggregate. No security/permission changes are included.

Frontend query owner clears old data on replaced input/API/reload, aborts superseded reads, rejects aborted responses, and displays errors with explicit retry. Mutations are single-flight and never auto-retried. [query and mutation lifecycle](https://github.com/neo-capiro/capiro-frontend/blob/e9df91d876eaad05d13fdd0707c1fe39d5affb62/apps/web/src/shared/capiro/queries.ts#L14). Keep independent task/report/name failure regions: a task 403 must not erase an independently successful office report. [existing browser negative case](https://github.com/neo-capiro/capiro-frontend/blob/e9df91d876eaad05d13fdd0707c1fe39d5affb62/apps/web/test/browser/desktop-detail-content.spec.ts#L196). None of these mechanisms defines a stale-plan business badge; unavailable/failed/empty must remain distinct.
