# Client storage usage — fixture-backed desktop evidence

All captures use the 1440 × 1040 light Portfolio browser viewport with synthetic test records. The meter reads the separate Core `GET /api/clients/:clientId/files/storage-usage` contract at pushed source commit [`948d4a7`](https://github.com/neo-capiro/capiro-backend/blob/948d4a7c8d500864c27f1aeb233a80903637591c/docs/integration/CLIENT-REGISTERED-STORAGE-USAGE-20261018.md). This source is pending receiving and has not been deployed or checked with a live authenticated session.

| Capture                                        | Fixture state and assertion                                                                                                                                                                                                                            |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| [Available](available-1440x1040.png)           | Authoritative registered usage is 7.4 MiB of a 10 GiB per-client allowance, rendered using Figma's MB/GB labels. The visible attachment has `byteSize: null`; the meter does not derive usage from the ACL-filtered file list. Upload remains enabled. |
| [Over allowance](over-allowance-1440x1040.png) | Registered usage is 10.4 GiB and `overAllowance: true` while the attachment list is still loading. The warning is informational; after the list loads, Upload is enabled. No hidden file count is invented.                                            |
| [Unavailable](unavailable-1440x1040.png)       | Core returns `incomplete_size_metadata` and null usage fields. The file table and Upload remain available, while no zero or progress meter appears. A separate browser assertion covers a 403 usage read with the list still usable.                   |

The focused Playwright checks also confirm that a successful synthetic upload confirmation refetches registered usage. In that test the later usage read returns 404 to model a route pending receiving; the upload still completes and the meter becomes unavailable. These checks do not qualify live routing, Core deployment, native auth, or actual storage bytes.
