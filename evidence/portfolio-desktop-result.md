## Design or source gaps

- The shared header/sidebar owners need to compare the header collapse control, sidebar row/divider positions, and Prospects active state at `/portfolio?type=PROSPECT` with the Portfolio frame. Those files are owned by the parallel Meri visual task.
- Figma has conflicting Agenda/Prep/Debrief versus Month/Week meeting headers and conflicting Objective intake form widths and controls. Neo should choose one current state for each.
- The 10 GB per-client storage allowance exists in Core product policy. This frontend receives only ACL-filtered attachment bytes, so it needs an authoritative client-wide usage aggregate before showing Figma's used/remaining or over-limit meter. A usage-unavailable state also needs a design.
- Quick Log is now wired to save direct Core commitments, edited occurrence time, and commitment/request due dates; fixture-backed direct save/Undo, wrong-due receipt, and blank When save-time checks passed 3/3. The combined activity plus Planner follow-up frontend command does not accept commitment or custom activity dates, and the UI disables that combination with an explanation. Direction, counterparty, objective/strategy links, custom Planner task title, and atomic commitment plus follow-up still need source contracts and approved interaction designs. [Exact frames and source boundaries](figma/decision-and-wiring.md).
- Figma preview values for engagement, urgency, deadline/request aggregates, weighted pipeline, win rate, and several Objective lifecycle measures do not have matching client-safe service fields. The build displays an unavailable state where needed.
- The live Figma asset host returned HTTP CONNECT 403 in this workspace. Existing named local vectors were checked visually against the rendered frames, but exact export-byte identity was not verified.

Mobile comparison is deferred by request. No deployment or live configuration change is part of this work.

Neither path was exercised against a live authenticated Core service. The final `@capiro/web` TypeScript check and optimized build passed, as did scoped ESLint, Prettier, the public package check, and `git diff --check`.

The repository architecture scan reported no boundary errors. It exits with review signals for size across the repository (530 at this commit), including several expanded Portfolio presentation files. The changed Portfolio files were reviewed for a single feature responsibility and for production data/authorization boundaries; no new service or permission authority was placed in presentation code. Live backend integration and mobile visual comparison were outside this desktop browser pass.
