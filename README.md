# Capiro frontend

Independent product frontend for Meri, Portfolio, Modules and Settings. Created at the human owner's request on10October2026. Meri backend and runtime remain separately owned in [meri-greenfield](https://github.com/neo-capiro/meri-greenfield); Portfolio and Modules backend services remain in [capirov2](https://github.com/neo-capiro/capirov2).

Read [the architecture](docs/ARCHITECTURE.md) and [implementation standards](docs/IMPLEMENTATION-STANDARDS.md) before changes. `apps/web` composes the shared shell and Meri Home; `packages/ui` owns reusable presentation, and `packages/meri-client` owns the public browser transport/projection adapter. Portfolio's transferred source is in `apps/portfolio-web` pending shared-app consolidation; see its [move outline](docs/portfolio-31/REPOSITORY-MOVE-OUTLINE.md) and [handover](docs/portfolio-31/handover-2026-10-11/HANDOVER.md). Modules and Settings remain disabled destinations. The Meri shell's Portfolio button remains disabled until the integration is actually connected and verified.

The current `/` entry and `/meri` screen are a disclosed, disconnected synthetic fixture. Home responsive repair and comparison with the finalized Figma Home reference are [independently accepted](docs/coordination/CODEX-MERI-HOME-FINAL-ACCEPTANCE.md). Browse workflows is visibly unavailable until its library is implemented. Authentication, other Figma screens, live service integration and deployment remain open.

Use Node24 and install from the repository root with `npm ci --ignore-scripts --no-audit --fund=false --update-notifier=false`. The root lock controls the workspace install. During the Portfolio repository transfer, `apps/portfolio-web` also retains its original lock for the independently built preview container; unify this when Portfolio joins the canonical `apps/web` build. `npm run dev` starts the local Meri web app; `npm run check` verifies public artifact bytes, all declared workspace typechecks, focused Meri tests, architecture and the21-case composed transport qualification. Run the Portfolio app's `check`, `format:check` and `test:browser` scripts separately from its workspace directory. `npm run build` compiles the public client before building the Meri web app; Portfolio has its own build until consolidation.

The15-case Elements qualification requires a fresh, hash-bound SSR receipt and is deliberately separate from routine `check`. Follow [its explicit preparation instructions](packages/qualification-elements/README.md), then run `npm run check:elements` with the receipt environment. Commands must not silently substitute an old receipt or imply live authentication, source policy, persistence or G1 qualification.

Public backend inputs and their acceptance limits are recorded in [vendor metadata](vendor/README.md) and [the migration acceptance](docs/coordination/CODEX-FRONTEND-MIGRATION-ACCEPTANCE.md). `node scripts/public-packages.mjs --help` documents the read-only artifact checker. Historical standalone locks and provenance remain qualification baseline data.
